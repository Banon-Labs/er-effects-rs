# Counters that are DECLARED but have NO WRITE SITE anywhere in the tree -- known debt.
# Enforced by scripts/check-counter-writers.py.
#
# This is the SUPERSET the sibling scripts/oracle-writers-allowlist.txt could never see. That gate
# fires only on `writes == 0 and reads > 0`; its own selftest pins the exclusion ("unread counters
# are out of scope"). So a counter that is declared, written nowhere, and never `.load()`ed was
# DELIBERATELY invisible to it -- and that is most of this list.
#
# THIS LIST MAY ONLY SHRINK, same contract as its sibling: the checker fails on any offender not
# listed here, and ALSO on any name listed here that is no longer an offender. Fixing a counter is
# not finished until its line is gone.
#
# To clear an entry, pick one:
#   WIRE   -- the feature exists and the signal is wanted: increment/store at the real site.
#   DELETE -- the feature is unbuilt, removed, or deliberately not installed: delete the counter AND
#             everything that prints it (log line, oracle key, and every script that consumes it).
# A permanently-0 counter is indistinguishable from a feature that ran and did nothing.
#
# CENSUS OF 2026-08-31, and a correction it produced. A handover put this at "151 of the 1,412
# counters declared in crates/er-telemetry-core/src/counters.rs". The 1,412 is exact. The 151 is
# not: it is what you get by dropping the by-reference and indexed-write rules that
# check-oracle-writers.py already documents (measured: 152 without them, 147 without by-ref alone,
# 66 with the full rule set). The true figure was 66 in counters.rs, 97 repo-wide -- and then 68/99
# once two false-WRITE shapes were fixed in the shared rule (`&& NAME.load(..)`, where the `&` of a
# boolean AND was reading as `&NAME`, and `let _ = &NAME;`, a discard binding). Those two shapes had
# been concealing PROFILE_ALPHA0_CLEARS and TITLE_CUSTOM_COVER_RUN_CALLS -- the latter being why
# `oracle_title_loaded_character_portrait_rendered` could never be true.
#
# NOTHING here is written from a macro, a `concat!`/`stringify!` construction, generated code, or
# another crate: the 13 files in the tree that construct identifiers inside macros were quarantined
# and checked, and not one offender's name appears in any of them.
#
# The entries deleted rather than allowlisted on 2026-08-31 were chosen by CONSEQUENCE -- printed in
# a log line, emitted as an oracle key, or consumed by a scoring script:
#   OWN_LOAD_M28_DISPATCH_FIRED   fed `world_stream_progress_watermark` in er-readiness-watch.py, a
#                                 run-STOPPING stall decision, documented there as "increments on a
#                                 working stream"; own_load_m28_dispatch is VERIFY-ONLY.
#   PROFILE_PERFRAME_SPARED_DRAWS / PROFILE_READBACK_DEFERRED_SOME / _NONBLACK
#                                 printed as `draws=` / `defer_some=` / `defer_nonblack=` on every
#                                 `lookat-phase-sweep` line (six such lines in the 2026-08-31 run).
#   PROFILE_BOUND_GX_RGB_MAX / _ALPHA_MAX
#                                 sentinel-initialised 0xffff, so `boundtex[...]` printed a
#                                 plausible 65535 rather than an obviously-absent 0.
#   PROFILE_ALPHA0_CLEARS         emitted `oracle_portrait_alpha0_clears`; the clear is compiled off.
#   TITLE_CUSTOM_COVER_RUN_CALLS  + the three `title_loaded_character_portrait_*` oracles it made
#                                 structurally false.
#   TITLE_PROFILE_VISIBLE_SURFACE_BIND_* (4)
#                                 five oracle keys, one of which er-readiness-watch.py copied into
#                                 the loading-screen-portrait event JSON a human reads.
#
